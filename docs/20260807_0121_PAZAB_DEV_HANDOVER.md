# PAZAB Dev Handover — 2026-08-07

## 오늘 작업 요약

### 1. 대타 홈 화면 구조 개편 — 공고/인력 탭 분리 + 공고 정렬 재설계

- **문제 인지**: 기존 `DaetaSosHome`은 "긴급 대타 공고" 가로 캐러셀(내 공고+남의 공고 혼재) + "실시간 대타 인력 목록"이 세로로 쌓여있어, 마켓 밀도가 올라갈수록 스크롤이 길어지고 목적이 다른 두 액션(공고 지원 vs 인력 직접 지목)이 한 화면에 섞이는 한계가 있었음.
- **구조 변경**: 상단에 "공고 ⇄ 인력" 탭 추가. 공고 탭 내부는 **내 공고(상단 고정, sticky)** → **긴급(가로 스크롤, 임박한 순)** → **다른 공고(세로 스크롤, 거리순→최신순)** 3구역.
- **긴급 판정 기준**: `escalation_stage >= 3`(동네 검증인력까지 풀었는데도 안 잡힘) OR 당일 시작 OR 시작 3시간 이내 — 새 필드 없이 기존 데이터로 계산.
- **카드 내용 정리**: 에스컬레이션 스테퍼+응답건수는 사장님 본인(내 공고)에게만 의미 있는 내부 정보라 판단, 남의 공고 카드에선 제거하고 대신 **매장명을 매장 홈(`/store/{id}`) 링크로**(집 아이콘 표시) 대체.
- `PostingCard`를 컴포넌트로 추출해 세 구역이 중복 없이 재사용.

### 2. 대타 거리 표시 — GPS 우선, "내 동네" 수동 설정 폴백

- 처음엔 매장/알바 프로필 주소를 기준점으로 썼다가, "이 거리는 대타 뛰러 갈 통근 거리인데 본인 가게 위치와는 무관하다"는 지적으로 **매장 주소 기준 완전 폐기**.
- 최종: **실시간 GPS 1순위** → 거부/실패 시 **`worker_profiles`에 저장된 "내 동네"**(신규 컴포넌트 `SetNeighborhoodSheet.tsx`, 카카오 주소검색으로 읍/면/동 단위 설정) → 둘 다 없으면 거리 숨김.
- 헤더에 `📍 신창면` 식으로 현재 설정된 동네를 상시 노출, 탭하면 바로 재설정 가능 (`AppHeader`의 기존 `rightActions` 확장 포인트 재사용, 헤더 컴포넌트 자체는 미변경).
- 카드에 `🚶 X.Xkm` 거리 배지 표시, 좁은 카드(긴급 줄 280px)에서 담당업무 등 한글 단어가 중간에 끊기던 문제는 `word-break: keep-all`로 수정.

### 3. 매장 좌표(lat/lng) 조용한 누락 버그 발견 + 수정 (심각)

- 실 DB를 REST API로 직접 조회해 확인: 사용자 테스트 계정의 매장 여러 곳이 `region`(주소 텍스트)은 정상인데 `lat`/`lng`이 null. 주소 지오코딩(Kakao API) 실패가 조용히 무시되고 있었음.
- 더 심각한 건 `DaetaRegisterModal.tsx` 6곳에 `lat: profile.lat || 37.5665`(서울시청 좌표) 폴백이 있어서, 좌표 없는 매장의 대타 공고가 **실제로 서울시청 좌표로 저장**돼 있었음 — 내 거리표시뿐 아니라 `notifyNearby`(동네 검증인력 반경 알림, 대타 SOS 핵심 로직)까지 서울 기준으로 계산되고 있었던 것.
- 서울 폴백 6곳 전부 제거, 좌표 없는 매장으론 대타 등록 자체를 막음(토스트로 안내). `StoreRegisterModal.tsx` 저장 시에도 좌표 필수 검증 추가해 재발 방지.

### 4. 대타 등록 폼 입력값 무결성 검증 강화

- "버튼 눌러도 아무 반응 없음" 버그를 조사하다 발견: 검증 실패 시 작은 인라인 텍스트만 떴는데 모달이 스크롤되는 구조라 안 보일 수 있었음 → 모든 검증 실패를 **토스트로도** 알리는 `fail()` 헬퍼 도입.
- 과거 날짜(수정 모드에서 이미 만료된 공고 재저장 시 특히), 업종 미선택, 종료시간이 시작시간보다 빠른 경우(야간 근무 안내로 대체, 차단은 아님) 등 검증 추가.

### 5. 대타 미체결 시 escalation 단계별 자동 시급 할증

- **배경**: "3시간 임박 긴급 표시가 실효성이 있나" 논의 → 등록 시점 1회성 할증 제안보다 **안 잡히고 단계가 오를수록 실시간으로 오르는** 구조가 더 강한 유인이라 판단(당근의 "가격 내려보기" 제안과 달리, 사장님이 펑크 대응 중이라 바쁠 때 자동 실행이 낫다고 결론).
- 등록 화면에 사장님이 **최대 할증 상한(%)**을 정하게 하고(0/10/20/30/50% 칩, 각 단계별 실제 금액 미리보기 표시), 그 상한 안에서만 자동으로 오르게 해 "예상 못 한 청구서" 리스크 차단.
- `daeta_sos_config`에 `stage2_pct`/`stage3_pct`/`stage4_pct`(기본 10/20/30%, admin 튜닝 가능) 신규. `lib/daetaEscalation.ts`의 `advancePostingStage`가 단계 전진 시 `min(단계별%, 사장님상한)`으로 시급 재계산 + DB 반영 + 알림 문구에도 새 시급 반영. `/api/daeta/sos`(팀원 없어 즉시 2단계 점프하는 경로)에도 동일 로직 적용.

### 6. 대타 미체결 만료 — 조회 시점 처리 → 크론 직접 처리 + 실패 알림 + 내역 기록

- **문제 발견**: 근무 시작 시각이 지나도록 안 잡힌 공고가 지금까지 **사용자가 대타 화면을 열 때만** `expired`로 조용히 바뀌었고(아무도 안 열면 무한 방치), 사장님에게 실패 알림이 전혀 없었으며, **지원자가 0명이면 `matches` 행 자체가 없어 대타 내역에도 영원히 안 뜸** — 가장 중요하게 챙겨야 할 실패 케이스가 완전히 비어있었음.
- `/api/cron/daeta-escalate`에 `expirePendingPostings()` 추가 — 5분마다 만료 공고를 직접 처리하고 사장님에게 "😢 이번 대타는 결국 못 구했어요" 알림 발송.
- `DaetaHistoryView.tsx`가 매칭 없이 만료된 내 공고도 별도 조회해서 목록에 합침(정산/노쇼신고 등 매칭 전용 액션은 자동으로 안 뜨게 가드).

### 7. 팀원 서류(보건증) 만료 알림 크론 신설

- 전체 코드베이스에서 "주기적으로 처리돼야 하는데 크론이 없는 곳"을 다시 훑어봄(Explore 서브에이전트 활용). `team_member_documents.expires_at`(보건증 유효기간) 배지 계산 로직은 있는데, 사장님이 팀원 상세 페이지를 직접 열어야만 보이고 알림이 전혀 없는 것을 발견.
- `/api/cron/doc-expiry` 신규 — 매일 1회, D-30/D-7/만료당일(이후 갱신 전까지 30일마다 반복) 알림을 **사장님+본인 알바생 양쪽에** 발송. `lib/notify.ts`에 `doc_expiry` 알림 타입 추가.

### 8. cron-job.org 등록 현황 재점검

- `daeta-escalate` 코드가 오래전부터 있었는데도 **cron-job.org에 실제로 등록된 적이 없었음**(0804/0806 핸드오버 문서에 "실동작 확인 필요"로만 계속 남아있던 항목의 실체). 사용자가 직접 등록 완료.
- `doc-expiry`도 동일한 방식으로 신규 등록 완료. 전체 크론 3→4개(`checkin`/`payslip`/`daeta-escalate`/`doc-expiry`), 코드는 있는데 미등록인 것은 더 없음을 전체 재확인.

### 9. 사장님 온보딩 2단계 정리

- "3단계 시작 가이드" 2단계가 "직원 초대 or 공고 올리기" 두 버튼이었는데, STRATEGY.md의 초대 공급 경로 원칙(콜드 공고보다 이미 일하는 사람 카톡 초대)과 어긋나는 "공고 올리기"를 제거하고 직원 초대 단일 액션으로 정리.

### 10. 매장 홈 팔로워 0명 표시 정리

- 팔로워 0명이 콜드스타트 단계에 빈 마켓처럼 보인다는 지적 → STRATEGY.md의 "피드/팔로우 기능은 코드 삭제 X, 네비 강등만" 원칙에 따라 팔로우 버튼은 유지하고 **0명일 때 텍스트만 숨김**.
